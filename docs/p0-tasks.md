## 1. タスクの大きさの決め方

### Pro プランの利用枠（2026-09 時点の公式の情報）

- 利用枠は **5 時間ごとに回復する枠**と、**週ごとの上限**の 2 つ。**1 日あたりのトークン数は公開されていない**（[Pro プランとは](https://support.claude.com/en/articles/8325606-what-is-the-pro-plan)、[利用枠の仕組み](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work)）
- **Claude Code と claude.ai のチャットは同じ枠を使う**（[Pro・Max で Claude Code を使う](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)）
- 残りは Claude Code の `/usage` で見られる。枠に達したら、回復を待つか、追加の利用を有効にする（[使用量の確認](https://code.claude.com/docs/en/monitoring-usage.md)）
- 公式の節約のしかた: 関係のない作業の間は `/clear`、CLAUDE.md は短く（200 行程度まで）、大きなファイルは中身を貼らずにパスで指す、日常の作業は Sonnet（[コストを抑える](https://code.claude.com/docs/en/costs.md)）

### このファイルでの決め方

1 日のトークン数の上限が公開されていないため、**「5 時間の枠 1 回に余裕をもって収まる」大きさ**で分けた。

| 大きさ | 読む設計書 | 作る・直すファイル | 目安 |
|---|---|---|---|
| **S** | 約 15 KB まで | 5 個くらいまで | 5 時間の枠の半分くらい |
| **M** | 約 30 KB まで | 10 個くらいまで | 5 時間の枠 1 回 |
| 人 | — | — | Claude Code をほとんど使わない手作業 |

- **1 日の目安: M を 1 つ、または S を 2 つ**。claude.ai のチャットを多く使う日は減らす。週の上限があるので、週 5 日ペースを基本にする
- **設計書を丸ごと読ませない**: 設計書は全体で約 388 KB（日本語が中心）あり、1 回読むだけで文脈の大部分を使う。セッションの中では応答のたびに読み直す形になるので、`tools/split-design.sh` で節ごとに分けたファイル（`docs/design/`）の、タスクに書いた分だけを読ませる
- **最初の 3 タスクで大きさを確かめる**: タスクの前後で `/usage` を見て、5 時間の枠の何割を使ったかを `docs/progress.md` に書く。M で 7 割を超えるなら以降のタスクを分ける。3 割に届かないなら S を 2 つまとめてよい
- モデルは基本 **Sonnet**（`/model` で確認）。Opus は枠の減りが大きいので、行き詰まったときだけにする

## 3. タスクを貼るときの定型文

新しいセッション（または `/clear` のあと）で、次を貼る。

```text
次のタスクをやって。進め方は CLAUDE.md の「タスクの進め方」のとおり。

（ここに、このファイルのタスクの見出しから次の見出しの前までを貼る）
```

- Claude Code は、コンテナにつながった VS Code のターミナルで起動する（Mac のターミナルでは起動しない）。「ローカルでの動作確認」のコマンドもコンテナの中で、URL は Mac のブラウザで開く
- 「読む設計書」はすべて `docs/design/` の中のファイル名。「〜の部分」は、そのファイルの中の見出しを探してその部分だけを読む、という意味
- エージェントが、書いていない節を読みたいと言ってきたら、許可するか、このファイルの「読む設計書」を直す
- すべてのタスクの完了の条件に、`pnpm lint` / `pnpm typecheck` / `pnpm test` が通ること（画面を変えたら `pnpm test:e2e` も）と、`docs/progress.md` の更新を含む（各タスクには書かない）

### L-04 ローカルの Postgres・Mailpit と DB の土台［M］

- 前提: L-03
- 読む設計書: `05-14.md` の「漏れを機構で防ぐ」の部分、`06-3.md`、`appendix-a/00-extensions.md`、`appendix-a/zz-rls-and-functions.md`（計 約 27 KB）
- やること
  - Postgres 16 と Mailpit は `.devcontainer/compose.yaml` で起動済み（コンテナの中からは `db:5432`・`mailpit:1025`。ローカルの管理者は `postgres`/`postgres`、DB 名は `beach`）。**`docker-compose.yml` は作らない**。コンテナの構成を変える必要があれば、変えずに私に聞く
  - ロール `app_owner`（テーブルの所有者）・`app_user`（アプリ）・`app_job`（ジョブ）・`app_backup`（BYPASSRLS・読み取りだけ）・`app_definer`（SECURITY DEFINER 関数の所有者）を作る `pnpm db:roles`（管理者の `POSTGRES_ADMIN_URL` で接続し、なければ作る・何度流してもよい。パスワードは `.env`）。`docker-entrypoint-initdb.d` は使わない（DB のボリュームはコンテナを最初に作ったときにできているので流れない）
