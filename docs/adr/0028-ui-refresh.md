# 0028 UI の刷新（レスポンシブ・配色・節目の演出）

## 背景

2026-09-21、利用者から 3 つの指摘があった。

1. PC でも操作する人が一定数いるのに、PC で使いにくい
2. 一覧と登録が同じページにあり、どこで何をするのか分かりにくい
3. 見た目が素っ気なく、操作していて楽しくない

いずれも設計書のとおりに作った結果である。

- §4.3 は「選手側は 375px 幅を基準に設計し、**PC は中央 1 カラムを広げるだけ。デザインを 2 系統に分けない**」としていた。実装は `max-w-xl`（576px）の 1 カラムで固定され、ブレークポイント（`sm:` / `md:` / `lg:`）は全画面で 1 つも使っていなかった。1920px の画面では、中央に細い帯が 1 本あるだけになる
- §4.5 原則 1 は「目的は『押した・変わった・終わった・間違えた』を伝えること。**飾りのための動き（紙吹雪、揺れ続けるアイコン、背景アニメーション）は入れない**」としていた
- §4.3 は「利用者の 9 割は Web 操作に慣れていない人（PC をほとんど使ったことのない高齢者を含む）」を前提にしている。この前提自体は変えない

## 決定

### 1. レスポンシブは 3 段にする（§4.3 を改める）

375px（スマホ）・768px（タブレット・小さい PC）・1280px（PC）の 3 段で作る。
「デザインを 2 系統に分けない」は残す。**同じ部品・同じ文言・同じ順序のまま、置き方だけを変える**。

- 幅は `src/components/ui/layout.tsx` の `PageMain` が決める。ページ側で `max-w-…` や `px-…` を書かない
  - `narrow`（既定）: 入力と読み物。1 行が長くなりすぎないようにする
  - `wide`: 一覧・ダッシュボード
  - `full`: 管理画面の表
- 主要操作の下部固定（§4.3）は**スマホだけ**にする。PC では本文の中に置く（`ActionBar`）
- 一覧はスマホで 1 列、PC で 2〜3 列にする

### 2. 一覧と登録はページを分ける

「一覧 + 追加フォーム」が同じページにある 4 か所（大会の資料・部のひな形・大会の部・協会員の受付）を、一覧のページと登録のページに分ける。登録のあとは一覧へ戻し、足した行を強調する（U-04）。

### 3. 配色（利用者の指定）

ベース `#ffffff`、メイン `#42B036`、アクセントはティール（海）。今までの青（`#1d4ed8`）はやめる。

`#42B036` は**白い文字を載せると 2.8:1** で、WCAG AA（4.5:1）にも UI 部品の 3:1 にも届かない。そこで `#42B036` を 500 とする 10 段階を作り、役割で使い分ける。

- `--brand-500`（`#42B036`）= 指定のメインカラー。**面・帯・進み具合・図・印**に使う（文字を載せない）
- `--color-primary` = `--brand-700`（`#2c7a22`）。**塗りつぶしのボタンと文字**。白文字で 5.37:1
- `--color-accent` = `--accent-700`（`#0b6664`）。二次の操作・リンク。白文字で 6.78:1
- 入力欄と押せるものの枠は `--color-border-strong`（`#8b958c`・3.1:1）。飾りの区切り線だけ `--color-border`（薄い）
- 補足の文字 `--color-muted` を `#6b7280`（4.83:1）から `#5c6660`（5.96:1）に濃くした

締切が近いときの橙（`#c2410c`）と危険の赤（`#b91c1c`）はそのまま。成功は緑の 800 と薄い緑の面にし、チェックと文字を必ず添えて、緑のボタンと見分けられるようにする。

### 4. 節目だけは大きな演出を許す（§4.5 原則 1 を改める）

**申込の完了・年度更新の申告の完了**の 2 か所に限り、紙吹雪などの「飾りの動き」を入れてよい。

- 1 回だけで止まる。繰り返さない
- `prefers-reduced-motion` が ON なら**演出そのものを出さない**。チェックと文字は残る
- 動きを見なくても文字だけで用が足りる（§4.5 原則 2 は残す）
- これ以外の場所（一覧・入力・読み込み中）では、今までどおり飾りの動きを入れない

日常の操作（押した・保存した・行が増えた）の演出は、今までどおり 150〜300ms の控えめなものにとどめる。
「楽しさ」は主に**動きではなく、色・影・余白・カードの浮き・ホバーの反応**で出す。

## 理由

- 「PC は 1 カラムを広げるだけ」は、`max-w-xl` の固定と組み合わさると PC で読みにくくなる。3 段にしても、部品と文言と順序が同じなら「2 系統」にはならない
- 配色の指定をそのままボタンに使うと、文字が読めない人が出る。**指定の色は一番目立つ面に使い、文字とボタンは同じ色の濃い段を使う**ことで、見た目の印象と読みやすさの両方を保てる
- 節目の演出は、そこで操作が終わるので、迷いを生まない。途中の画面に飾りを入れると、慣れていない人が「何が起きたのか」を探してしまう

## 却下した代替案

- **PC 用の画面を別に作る**: 画面が 2 倍になり、文言と権限の判定が二重になる。§4.3 の「2 系統に分けない」はこの意味では正しい
- **`#42B036` をそのままボタンに使う**: 白文字で 2.8:1。高齢の利用者に読めない
- **`#42B036` に黒い文字を載せたボタン**: コントラストは足りるが、ほかのボタンと見た目がそろわず、「押せるもの」の見分けが付きにくくなる
- **全画面に演出を入れる**: §4.3 の「利用者の 9 割は Web 操作に慣れていない」という前提に反する
