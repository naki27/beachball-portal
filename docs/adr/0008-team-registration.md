# 0008 チームで登録・チーム情報の編集

## 背景

A-14 で `/[スラッグ]/teams/new`（チームで登録）とチーム情報の編集を作った。設計書 §5.11「チームの作り方」は「チーム名だけで作成完了」「同名のチームがあれば警告」「協会員の登録をするチームかは代表者が設定し、テナント管理者も変えられる」と書くが、次の点は書かれていない。

1. 権限表（§3.2・`src/lib/authz.ts` の `ACTIONS`）に「チーム情報の編集」の行がない
2. 「同名」の判定のしかたと、警告の出し方（API の形）
3. 項目の「活動地域（任意）」を入れる列が `teams`（付録 A から作った表）にない
4. 入力の上限・形

## 決定

1. **`ACTIONS.editTeam`（最も低いロール = チームの代表者）を足す**。テナント管理者は包含で変えられる。API・画面とも `can(role, "editTeam")` で判定する
2. **同名は `normalizeName()` でそろえて比べる**（全角・半角、空白、大文字・小文字、ひらがな・カタカナの違いを同じとみなす）。`POST /api/[slug]/teams` は同名があれば **409**（`error.sameName = { count, mine }`）を返し、画面は「同じ名前のチームが N チームあります」と、自分が代表者を務める同名のチームへのリンク、「別のチームとして登録する」ボタン（`confirmSameName: true` で送り直す）を出す。ほかの人のチームは数だけ（チーム名は公開の情報だが、代表者や連絡先は出さない）
3. **活動地域は入れない**（列を足さない）。必要になったら付録 A を直してから足す
4. チーム名は必須・50 文字まで、ふりがなは任意・ひらがな／カタカナ・50 文字まで、連絡先メールは `normalizeEmail()` の形、電話は数字・`+-()`・空白で数字 10〜15 けた。前後の空白を除き NFKC でそろえる（`src/lib/teams/team-input.ts`。画面とサーバーで同じ関数）
5. チーム情報の編集の API は、**404（URL の協会にない・削除済み・ID の形が違う）→ 403（代表者でない）→ 400（入力の誤り）** の順に判定する

## 理由

- 1: §5.11 が「代表者が設定し、テナント管理者も変えられる」と明記しており、既存の行（`manageRoster` など）はどれも意味が違う。権限表を 1 か所のデータに保つ決まりなので行を足す
- 2: 「誤って新規作成するのを防ぐ」が目的なので、表記の揺れも拾う。正規化の実装は 1 つだけにする決まりがあるため normalize.ts を使う。409 は「業務上の条件で受け付けない」に当たる
- 3: 表を変えるとマイグレーションが要り、設計書の付録 A とずれる
- 5: §3.1 の判定の規則（資源 → 権限）に、入力の検査を最後に足した。代表者でない人に入力の誤りを先に知らせない

## 却下した代替案

- 同名の確認を別の API（`GET …/teams?name=`）に分ける: 送信の 1 回で済むほうが単純。確認後に作る間に同名が増えても、警告の目的からは問題ない
- 同名のチームの代表者名を見せる: 「他チームの情報」はテナント管理者だけ（§3.2）
