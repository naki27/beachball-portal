# 0036 Brevo のクリック計測は画面で切る。R2 のバックアップ用バケットは別のキーで触る

## 背景

X-01 で本番用の設定を入れるときに、設計書に答えのない 2 つが出た。

1. 設計書 §11.2 は「トランザクションメールでは開封・クリックの計測を**オフ**にする」（本文の URL が第三者のサーバーを経由しないように）と決めているが、
   **Brevo の API（`POST /v3/smtp/email`）で 1 通ごとに指定できるか**が【要確認】のままだった
2. §6.5「補足」は、バックアップ用バケットに渡すトークンを「そのバケットへの書き込みだけ」にすると決めている。
   いまの `src/lib/storage/index.ts` は**1 組のキーで 3 つのバケットを触る**作りで、アプリにもバックアップ用バケットの権限が渡っていた

## 決定

### 1. クリック計測は Brevo の画面で切り、1 通ごとには記録の匿名化だけを付ける

- Brevo の API のリクエストに、**リンクの書き換え（クリック計測）を 1 通ごとに切るフィールドはない**（2026-10-03 に API のリファレンスで確認）。
  宛先ごとの `contactPixelTrackingConsent` で「開封とクリックの記録を匿名化する」ことはできるが、**URL が Brevo を経由するのは止められない**
- そのため、**リンクの書き換えは Brevo の画面の設定で切る**。手順は `docs/ops.md` §9 に書き、実際に切るのは H-01
- 送信時は全通に `contactPixelTrackingConsent: false` を付ける（画面の設定を切り忘れても、記録だけは残らないようにする）
- 切れているかは H-05 のテスト送信で、届いたメールの本文の URL が書き換わっていないかを目で見て確かめる

### 2. バックアップ用バケットは別のキーで触る

- `R2_BACKUP_ACCESS_KEY_ID` / `R2_BACKUP_SECRET_ACCESS_KEY` を足し、**バケットごとに資格情報を持つ**形にする（`src/lib/storage/r2.ts` の `R2BucketConfig`）
- このキーは**日次ジョブにだけ渡す**。アプリには渡さないので、アプリからバックアップ用バケットを触ろうとすると、
  通信する前に「`R2_BACKUP_ACCESS_KEY_ID` を渡していない」で止まる
- R2 の画面のトークンでは「書き込みだけ」にできない（2026-10-02 に確認）。そこをどう受け入れるかは X-03 で決める。
  本 ADR は「**別のキーにして、渡す先を分ける**」ところまでを決める

## 理由

- 1 通ごとに切れないものを、コードで切れるかのように書くと、切り忘れに気づけない。画面の設定を運用手順に書くほうが確実
- 匿名化の指定は 1 行で済み、画面の設定が外れたときの保険になる
- 鍵を分ければ、アプリ（公開されている入り口を持つ）が漏れても、全員の生年月日を含むバックアップには届かない。
  「使うサービスにだけアクセス権を付ける」（§6.3）とも合う
- 「鍵がない」を実行時のエラーにするのではなく**触る前に止める**ことで、アプリのキーでバックアップ用バケットを触ってしまう事故を防げる

## 却下した代替案

- **Brevo のアカウントを分けて、計測なしのアカウントから送る**: 無料プランの送信数（1 日 300 通）をさらに分けることになり、§11.2 の心配（上限に当たると誰もログインできない）が増える
- **メール本文の URL を短縮せず、計測を気にしない**: §11.2 の決定（第三者のサーバーを経由させない）に反する
- **バックアップ用バケットをアプリのキーのままにする**: 実装は要らないが、アプリが漏れたときに生年月日を含むダンプまで届く
- **バックアップ用の保存先を別の `StorageAdapter` にする**: バケットの選び方（`StorageBucket`）が 2 通りになり、「ロジックの単一実装」から外れる
