# 0007 入口・マイページ・ヘッダのメニュー

## 背景

A-13 で `/`（役割を持つ協会の一覧）・`/mypage` の骨組み・協会の切り替えメニューを作った。設計書 §5.3・§5.14「協会をまたぐ画面」「テナントの切り替え」に書かれていない次の点を決める必要があった。

1. 切り替えメニューの置き方（375px 幅のヘッダに「マイページ」「協会を切り替える」「ログアウト」を並べると協会名が折り返す）
2. ログアウトしたあとの行き先（`/` は未ログインだと 403 になった）
3. 表示名の整え方と長さの上限（§14-13 はこのタスクで読まない節）と、変更の API
4. 運営管理者の `/` に何を出すか（切り替えメニューは「全協会」と書かれている）

## 決定

1. **ログイン中はヘッダ右上に「メニュー」1 つ**（`<details>`）。中身は「マイページ」「運営管理」（運営管理者だけ）「協会を切り替える」（関わる協会が 2 つ以上のときだけ。表示中の協会に印）「ログアウト」。画面を移ると閉じる
2. **協会のページからのログアウトはその協会のトップ**、協会に属さないページからは **`/login`**
3. **表示名は前後の空白を除き、続く空白（全角を含む）を 1 つにまとめ、空なら「表示名なし」（NULL）。30 文字まで。制御文字は不可**（`src/lib/account/display-name.ts`）。変更は `PATCH /api/me`（`{ displayName }`）
4. **運営管理者の `/` は、ほかの人と同じく役割を持つ協会だけ**を出し、「運営管理」へのリンクを添える。切り替えメニューは全協会

## 理由

- 1: §5.14 は「画面右上のメニューに『協会を切り替える』を置く」と書いている。ボタンを並べるより、1 つのメニューにまとめたほうが 375px 幅で崩れない
- 2: ログアウト直後に 403（「ログインが必要です」）を見せるのは不自然。協会のページにいた人は、その協会の公開の画面に残るのが自然
- 3: 表示名は招待のメールや運営の画面で「招待した人」として出る。メールの 1 行に収まる長さにする。§14-13 と食い違えば直す
- 4: `/` は「役割を持つ協会の一覧」（§5.14 の表）。全協会は `/platform` で見られる

## 却下した代替案

- ヘッダに「ログアウト」を出したまま、別に切り替えメニューを置く: 375px で協会名が 2 行になる
- ログアウト後に `/` へ移る（A-09 の形）: 未ログインの `/` は 403 になったため
- 表示名に `normalizeName()` を使う: 名寄せ用の正規化（空白・記号を消す）で、表示には使わない決まり
