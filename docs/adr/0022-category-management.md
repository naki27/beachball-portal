# 0022 部の管理の細部（プリセットの呼び名・締切を揃える操作・基準日の確定）

## 背景

B-05 で大会の部の管理（プリセットからの一括追加・部ごとの締切／基準日／上限・基準日を変えたときの確定）と、テナント設定での部門プリセットの編集（`/[スラッグ]/admin/association`）を作った。設計書 §5.4 に書かれていない次の 5 点を決める必要があった。

1. `category_presets` を画面で何と呼ぶか。§4.4 の対応表に `tournament_categories` の行（「部」）はあるが、プリセットの行がない
2. 「部門の締切も揃える」チェックを押したとき、部の締切をどう書き換えるか
3. 使われているプリセットを消せるようにするか
4. 基準日を「新しい基準日で確定する」で上書きしたとき、`entry_audits` に何を残すか
5. 部の条件の文章（「全員が40歳以上です」など）をどこに置くか

## 決定

1. **「よく使う部」**と呼ぶ。プリセット・部門・カテゴリは画面に出さない
2. **部ごとの上書き（`tournament_categories.entry_end_at`）を NULL に戻す**。大会の締切の値を各部にコピーしない
3. **消せない（409）**。代わりに「新しい大会の候補に出さない」（`is_active = false`）を案内する
4. **申込ごとに 1 行**、`before` / `after` に「選手の位置（`position`）と年齢」だけを入れる。`after` には適用した基準日も入れる。氏名・生年月日は入れない
5. **`src/lib/tournaments/category-text.ts` の 1 か所**（`categoryConditionText`）。管理画面・大会詳細（B-06）・申込ページ（B-07 以降）で同じ文を出す

## 理由

- 1: `CLAUDE.md` の規約「内部の用語を画面に出さない」。利用者（協会の役員）にとっては「毎年使う部の一覧」なので、その言い方をそのまま使った。§4.4 を差し替えるときに行を足す
- 2: NULL が「大会の締切に従う」を意味すると `deadline.ts` の `effectiveDeadline` で決めている。値をコピーすると、次に大会の締切を変えたときにまた食い違う（§5.4 が「自動では追従しない」と書いているのは上書きの話で、揃えたあとは追従してほしい）
- 3: プリセットは過去の大会の部が `preset_id` で指しており、判定に使う数値（コートの人数・混合の最少人数）もそこから読む。消すと過去の申込の判定根拠が消える。外部キーでも守られているが、409 の文言で「候補から外す」へ誘導したほうが分かりやすい
- 4: 規約「個人情報をログ・エラーメッセージに含めない（生年月日は特に）」。あとから「誰の年齢がいつ何に変わったか」をたどるには、申込 ID と位置があれば足りる
- 5: 同じ文言を管理画面・公開ページ・申込ページの 3 か所で書くと必ずずれる。判定そのものは `eligibility.ts`（唯一の実装）で、こちらは表示専用と役割を分けた

## 却下した代替案

- プリセットを「部のひな形」と呼ぶ: 「ひな形」は文書の語感が強く、役員の会話では「いつもの部」に近い言い方をしていた
- 基準日を変えたら自動で再計算する: §5.4 が「勝手に申込を無効化しない」と明記している。確定を人が押す形は、要項の直し間違いを戻せるようにするため
- 確定を申込ごとに選べるようにする: 基準日は大会（または部）の設定なので、一部の申込だけ古い基準日で残ると集計が合わない。大会単位でまとめて確定する
- 部の一括追加で、すでにある部を 409 にする: 18 件のうち 3 件だけ足したいときに、毎回チェックを外させることになる。飛ばした数を結果に返して知らせる形にした
