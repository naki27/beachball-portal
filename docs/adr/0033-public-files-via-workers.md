# 0033 公開用ファイルは Cloudflare Workers で配信する（第 2 案。0026 の第 1 案を変更）

## 背景

ADR 0026 は、公開用バケットを独自ドメイン（例: `files.entry.…`）で配信する第 1 案を前提にした。これは `entry.` のサブドメインを Cloudflare で扱えること（§14.9 D-4）が前提だった。

本番の準備（`docs/deploy-prep.md` §4）で確かめたところ、次のことが分かった。

- Cloudflare の無料プランにはルートドメインしか追加できない（「ルートドメインを入れてください」というエラーになる）。サブドメインだけを追加する機能（Subdomain setup）は Enterprise プランだけ。→ D-4 は「任せられない」
- 第 1 案をとるには、`fukuoka-city-beachball.org` 全体の DNS を Cloudflare に移すしかない。そうすると、協会のいまのサイトやメール（MX・SPF・DKIM・DMARC）のレコードもすべて移ることになる

## 決定

**公開用バケットは Cloudflare Workers で配信する（第 2 案）。** URL は `*.workers.dev` を使う。

- アプリは変えない。`PUBLIC_FILES_BASE_URL` に Workers の URL を設定するだけにする（ADR 0026 のとおり）
- Workers は、公開用バケットだけを R2 のバインディングで読み出し、GET（と HEAD）にだけ答える。オブジェクトに付けたメタデータ（`Content-Type`・`Content-Disposition`・`Cache-Control`）をそのまま返し、ないものは 404 にする
- Workers のコードと設定は X-05 で作る
- `*.workers.dev` には Cloudflare のキャッシュが効かないことがある。資料の数と回数が小さいので問題にしない
- 1 日の上限を超えると、その日（UTC の 0 時＝日本時間の 9 時まで）は資料が開けなくなる。上限に近づく規模になったら、有料プランか第 1 案を検討する

## 理由

- DNS を移すと、このシステムの外（協会のサイト・メール）にまで影響が及ぶ。レコードが 1 つ漏れるだけでメールが届かなくなるおそれがあり、Wix の DNS に頼る機能（サイトの接続など）も設定し直しになる。その手間と危険に比べて、得られるもの（PDF とロゴを独自ドメインで配信できること）が小さい
- 費用がかからない。Workers の無料プランは 1 日 10 万リクエストまでで、超えても請求されずエラーになるだけ。大会のある月で 500 回ほどの見込みなので、桁違いに余裕がある。R2 の読み取り（Class B）は月 1,000 万回まで無料
- 利用者が共有するのはアプリの URL なので、あとで第 1 案に移っても共有済みのリンクは壊れない

## 却下した代替案

- **ドメイン全体の DNS を Cloudflare に移す（第 1 案）**: 上の理由で見送る。協会が DNS を移すと決めたら、`PUBLIC_FILES_BASE_URL` を変えて切り替える
- **配信用に別のドメインを取る**: 年間の費用がかかり、サイトと名前もそろわない
- **アプリが R2 から読んで返す（第 3 案）**: ADR 0026 のとおり、最後の手段にとどめる
