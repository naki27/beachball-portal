# 0029 読み込みの骨組み（`loading.tsx`）は管理画面だけに置き、403 は layout で返す

## 背景

設計書 §4.5 は「読み込みが 1 秒を超えたら内容の形をした薄い骨組み（スケルトン）」「3 秒を超えたら『少々お待ちください』」を求めている（Cloud Run のコールドスタート対策・§6.5.2）。
Next.js でこれを出すには、区画に `loading.tsx` を置く。

しかし `loading.tsx` を置くと、その区画は Suspense の内側になり、**中身の読み込みより先に骨組みが流れ始める**。
流れ始めたあとに `forbidden()` / `notFound()` が呼ばれても、応答はすでに 200 で始まっているため、**403・404 が 200 になる**。

設計書 §3.1 と CLAUDE.md の「判定の規則」は、
**URL の協会と資源の協会が違う・資源がない → 404／権限がない → 403（未ログインも 403。リダイレクトしない）**
を明確に求めている。実際、`src/app/[slug]/loading.tsx` を置いたところ、E2E の
「`/sawara/admin` は 403」「登録のページは未ログインなら 403」が 200 を受け取って落ちた。

## 決定

**区画ごとの `loading.tsx` は、`[slug]/admin` にだけ置く。**

`loading.tsx` は**同じ区画の `layout.tsx` より内側**に Suspense の境界を作る。
そこで、協会の管理者かどうかの検査を `src/app/[slug]/admin/layout.tsx`（＝境界の外側）で行い、
管理者でなければそこで 403 を返す。骨組みが流れ始めるのは、検査を通ったあとだけになる。

- `[slug]/admin/layout.tsx`: `assertAccessOrDeny(checkAccess(role, "manageTournaments", principal))`
- `[slug]/admin/loading.tsx`: `PageSkeleton`（中身は `DelayedSkeleton`。1 秒未満では何も出さず、3 秒で「少々お待ちください」）
- **各ページ・各 API の権限の検査はそのまま残す**（二重に見る・§3.1）。layout の検査は見た目のためではなく、
  「骨組みを出してよい相手か」を先に決めるためのもの

**選手側（`[slug]` 直下・`(site)`）には `loading.tsx` を置かない。**
これらの区画では、ページそのものが 403・404 を返すため、境界を作るとステータスが壊れる。
代わりに、遅いのが分かっている部分（確認ページの読み込みなど）で `DelayedSkeleton` を部品として使う。

## 理由

- **403・404 のステータスは、骨組みより優先する**。判定の規則は設計の根幹で、テストもそこを見ている
- 管理画面は PC から長く使う画面で、一覧の件数も多い。骨組みの効き目が一番大きい
- 選手側は 1 ページの中身が小さく、1 秒を超える読み込みはコールドスタートのときに偏る。
  コールドスタートでは**サーバーが応答を始めるまで**が遅いので、`loading.tsx` があっても骨組みは出ない
  （骨組みを出すには、まずサーバーが応答を始める必要がある）。つまり選手側に置いても得られるものが小さい

## 却下した代替案

- **全区画に `loading.tsx` を置く**: 403・404 が 200 になる。§3.1 に反する
- **`loading.tsx` を置いたうえで、すべてのページの権限の検査を layout に移す**: 検査の場所が散らばり、
  「認可はページ・API で必ず検査する」という決まりが曖昧になる。区画が増えるたびに層を足すことになる
- **`useLinkStatus` で画面ごとに押した印を出す**: `<Link>` の子でしか使えず、リンク 1 つずつに部品を足すことになる。
  「読み込みが 1 秒を超えたら骨組み」の代わりにはならない（P1 で、押したリンクの印として検討してよい）
