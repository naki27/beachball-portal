# 0016 問い合わせフォームの細部

## 背景

A-22 で問い合わせフォーム（設計書 §5.10・§11）を作った。設計書に書かれていない次の点を決める必要があった。

1. `/contact`（テナントに属さない入口）で、宛先の既定をどちらにするか
2. 転送メール（`contact_forwarded`）に何をどこまで載せるか。本文は `mail_logs` に持てない（§11「送り方」）
3. 協会の連絡先メール（`associations.contact_email`）も `CONTACT_TO` も未設定のときの振る舞い
4. 管理画面の一覧の既定と、対応済みにしたあとの取り消し
5. `platform_contact_messages`（テナントに属さない表）の RLS

## 決定

1. **既定は置かない**。「どちらへのお問い合わせですか？」を選ぶまで入力欄を出さない。協会のページ（`/[スラッグ]/contact`）から来たときは選ばせない。`/contact` で選べる協会は**役割を持つ協会**、役割がなければ全協会（§5.10）
2. `mail_logs.params` に入れるのは**受付番号（`messageId`）と宛先の種類（`scope`）だけ**。雛形が送る直前に `contact_messages` / `platform_contact_messages` から読み、転送には種別・お名前・**返信先**・受付番号・本文を、受付控えには種別と本文の写しを載せる。どちらにもリンクは載せない
3. どちらも未設定なら**転送しない**（保存と受付控えだけ）。管理画面の一覧には出るので問い合わせは失われない
4. 一覧の既定は**未対応だけ**。「すべて」に切り替えられる。対応済みの行は「**未対応に戻す**」で戻せる（押し間違いを取り消せる）
5. **RLS は置かず権限だけ**（0003 の「テナントに属さない表」と同じ）。読み書きできるのは運営管理者だけで、その判定はアプリ側（`managePlatformContacts`）

## 理由

- 1: 宛先を間違えると、協会の話がサイトの運営者に（その逆も）届く。既定を置くと押し間違いが起きる。役割を持つ協会を先に出すのは、ほとんどの人が自分の協会に送るため
- 2: 本文を `params` に写すと、送信待ちの表に個人情報が二重に残る（§11「送り方」・付録 A）。返信先を載せるのは、運営がメールの返信でそのまま応対できるようにするため（この仕組みの中に返信の機能は作らない・§1.2）
- 3: 転送先がないことを理由に受け付けを断ると、ログインできない人の最後の行き先がなくなる（§5.10）
- 4: 未対応が既定なら「やること」がそのまま見える。取り消せないと、押し間違いを直す手段が DB しかない
- 5: テナントに属さない表に `association_id` はなく、RLS で書ける条件がない。同じ形の表（`users`・`sessions`・`platform_admins`）と揃える
