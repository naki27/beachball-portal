# 0020 部門の資格バリデーションの細部（文言・警告・添字）

## 背景

B-03 で `src/lib/eligibility.ts`（設計書 §5.5(e)・付録 E）を作った。付録 E の擬似コードに対して、次の 4 点は決める必要があった。

1. メッセージの中の「部門」という言い方（付録 E は「この部門（男子）の対象ではありません」と書いているが、§4.4 の対応表では画面には「部」と出す）
2. エラーをどの選手枠の下に出すかを、呼ぶ側にどう伝えるか
3. 合計年齢の部の「基準に届かない可能性があるときは注意文を出す」の条件
4. 登録人数がコート上の人数（`court_size`）より少ないときの合計年齢の出し方

## 決定

1. **画面に出る文言は「部」にする**（`この部は40歳以上が対象です（早良次郎さんは39歳）`・`早良花子さんはこの部（男子）の対象ではありません`）。混合の文言は付録 E のまま「混合の部は…」
2. `EligibilityIssue` に **`playerIndex?: number`**（渡した `players` の添字）を足す。選手を名指しするエラー（性別・年齢の下限）だけに付け、チーム全体のエラー（混合の男女比）には付けない
3. **有効な組み合わせの最大が基準に届かないとき**と、**最小だけが届かないとき**で文言を分けた warning を 1 件出す。どちらも送信は止めない（`hasEligibilityError` は error だけを見る）
4. **いる人だけで数える**（`slice` の結果をそのまま合計する）。人数の下限は大会の `team_size_min` で別に見る（B-09）

## 理由

- 1: `CLAUDE.md` の規約「画面の文言は設計書 §4.4 の対応表に従う。内部の用語を画面に出さない」。§4.4 は `tournament_categories` = 「部」と決めている。付録 E は擬似コードで、文言の正本は §4.4
- 2: §5.5 は「エラーは入力ページの該当する選手枠の下に表示する」「誰がどう不足しているかを名指しで」と決めている。文字列から選手を探し直すより、作った側が添字を返すほうが取り違えない。ID ではなく添字にしたのは、送信前の入力（まだ `member_id` のない手入力の選手）でも使えるようにするため
- 3: 「合計年齢は判定しない」（§14-20）と「届かない可能性があるときは注意文」（§5.5(e)）を両立させる。どの 4 人でも届かないときと、組み合わせ次第のときは利用者の受け取り方が違うので分けた
- 4: 4 人に足りない登録は人数の下限で必ず弾かれる。ここで 0 を足したり例外にしたりすると、入力途中の画面で数字が跳ねる

## 却下した代替案

- 合計年齢が基準に届かないときを error にする: §14-20 の「システムで判定せず、計算結果を見せるだけ」に反する
- 混合の判定を「当日の編成の組み合わせを全部試す」形にする: `court_size` と最少人数が設定値であるかぎり、「男 ≧ mixed_min_male かつ 女 ≧ mixed_min_female」と同値（§5.5(e) の説明どおり）。総当たりにすると読みにくいだけ
- メッセージの組み立てを画面側に置く: 同じ判定を API とジョブでも使うので、文言も 1 か所に置く（`src/lib/eligibility.ts`）
