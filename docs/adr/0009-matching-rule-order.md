# 0009 名寄せのルールの適用順と、別名を使わないこと

## 背景

A-15 で `src/lib/matching.ts` を作った。設計書 §8.3 のルール 2・3 は次のように書かれている。

- 2: 氏名・生年月日・**性別**が一致する探索対象がちょうど 1 件 → 結びつける。氏名・生年月日は一致するが性別が違う → 新規＋要確認
- 3: 氏名・生年月日が一致するメンバーが**複数** → 新規＋要確認

「氏名・生年月日が同じ人が 2 人いて、性別が合うのは 1 人だけ」のとき、2 と 3 のどちらに当たるかが書かれていない。また、`member_aliases`（旧姓・表記ゆれ・付録 A）を名寄せに使うかも §8.3 には書かれていない。

## 決定

1. ルールは**番号の順に当てる**。性別まで一致する人がちょうど 1 人ならルール 2 で結びつける。ルール 3 は「性別まで一致する人が複数」のときにする。性別まで一致する人がいなければ（氏名・生年月日だけ一致）ルール 2 の後半（性別違い）
2. **`member_aliases` は名寄せに使わない**（§8.3 のルールに出てこないため）。別名で探す必要が出たら、§8.3 を直してから `listMatchCandidates()` に足す
3. 判定の結果は `MATCH_OUTCOMES`（「ルールと記録の対応」の表をデータにしたもの）に従う。テストは表から生成する

## 理由

- 1: 性別は §8.3 で名寄せのキーに含まれており、性別の違う同姓同名・同一生年月日の人は機械的に分けられる。性別が合う 1 人に結びつけても誤りにならない
- 2: 設計書にないキーで結びつけると、自動で結びつく範囲が広がる。§8.3 の方針（自動で結びつけるのは氏名・生年月日・性別の完全一致だけ）を保つ
- 3: 表と実装がずれないようにする（権限表と同じやり方）

## 却下した代替案

- 氏名・生年月日が一致する人が 2 人以上なら、性別にかかわらずルール 3（新規＋要確認）にする: 性別が違う家族（双子など）がいるだけで、毎回新しい人物が作られて要確認が増える
