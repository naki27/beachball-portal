# 0014 代表者の委譲・解除とチームの無効化の細部

## 背景

A-20 で代表者の追加（招待）・解除と、チームの無効化・有効に戻す（`src/lib/teams/admins.ts`・`setTeamStatus`）を作った。設計書 §5.11「代表者の委譲」「チームの無効化と削除」に書かれていない次の点を決める必要があった。

1. 代表者どうしに、ほかの代表者の何を見せるか
2. 申込（`entries`）の表がまだない段階で、「締切前の申込が残っていれば 409」をどう置くか
3. 個人登録の無効化
4. 無効にしたチームの閲覧と、代表者を降りたあとの画面

## 決定

1. **表示名とメールアドレス**を見せる（`/[スラッグ]/teams/[id]/admins`）。誰が代表者か分からないと解除の判断ができないため。選手には見せない（この画面は代表者だけ）
2. **`src/lib/repo/entries.ts` の `countOpenEntries()` を口だけ作り、常に 0 を返す**。B-01 で `entries` を作ったら、締切（`deadline.ts`）と状態で数える形に置き換える。無効化の判定はテナント管理者では見ない（§5.11: 管理者は無効化できる。申込は自動で取り消さない）
3. **個人登録は無効にできない（409）**。個人登録は申込のチームの候補にもならず、無効化の意味がない
4. 無効にしたチームも、選手・代表者はこれまでどおり見られる（申込と招待だけ止まる）。自分で代表者を降りたら、その画面は見られなくなるのでマイページへ移す

## 理由

- 1: §5.11「代表者を外すこともできる」を画面にするには、対象を識別できる必要がある。表示名は任意なので、なければメールアドレスしか手がかりがない
- 2: 判定の場所（`setTeamStatus`）と条件を先に固定しておけば、B-01 では数える関数を差し替えるだけで済む
- 4: §5.11 の表は「申込のチームの候補に出さない」「返事待ちの招待はすべて取り消す」「代表者の行は残す」で、閲覧を止めるとは書いていない

## 却下した代替案

- 代表者の追加を承諾なしで即時にする: §5.11（v0.9）で「どちらの経路も相手が承諾して初めて代表者になる」と決まっている
- 無効化の 409 を B-01 まで作らない: 判定の口がないと B-01 で無効化の処理に手を入れることになる
