# 0032 「個人で登録する」をテナントごとに出す／出さない

## 背景

設計書 §5.11「個人登録」は、1 人で大会に申し込む人のために**内部で `kind = individual` のチームを 1 つ作る**仕組みを決めている。
ただし、これは**どの協会でも使う**前提で書かれていた。K-02 で「利用しない協会もあるので、出す／出さないを切り替えたい」という要望が出た。

出さない協会で入口だけを隠しても、URL を直に開けば登録できてしまう。**画面と API の両方で止める**必要がある。

## 決定

**`associations.individual_registration_enabled`（boolean・既定 true）を足し、協会の設定の画面で切り替える。**

- 既定は `true`（いままでどおり受け付ける）。マイグレーション 0019
- 切り替えられるのは**テナント管理者**（§3.2 `manageTournaments` と同じ入口。`PATCH /api/[slug]/admin/association`）
- 受け付けないときの見え方:
  - トップ（`/[スラッグ]`）とマイページの「個人で登録する」のリンクを出さない
  - `/[スラッグ]/teams/new?kind=individual` は **404**（「チームで登録」とのタブも出さない）
  - `registerIndividual()`（`src/lib/teams/self.ts`）が **404** を投げる。API もこれをそのまま返す
- **すでに個人で登録した人はそのまま**。チームも人物も消さない（申込の履歴が壊れるため）

## 理由

- 判定の規則（§3.1）では「資源がない → 404」。**その協会には個人登録という入口がない**ので、403 ではなく 404 にした。
  403 は「ログインすれば見られるかもしれない」と読めてしまう
- 検査を `registerIndividual()` の中（`withTenantOn` の tx の中）に置いたのは、**入口が増えても素通りできないようにする**ため。
  画面側の 404 は「見せない」ための早い判定で、最後の砦は 1 か所（§ロジックの単一実装）
- 環境変数ではなく DB の列にしたのは、協会ごとに違う設定で、運営が SQL を触らずに変えられる必要があるため

## 影響

- `AssociationLink`（`listMyAssociations` / `listAllAssociations`）に `individualRegistrationEnabled` が増えた。マイページの出し分けに使う
- 協会の設定の画面（`/[スラッグ]/admin/association`）が「よく使う部門」だけでなくなった。今後の設定もここに並べる
- 「個人で登録する」を止めたあとに戻すと、また登録できる（止めている間の申し込みは増えない）
