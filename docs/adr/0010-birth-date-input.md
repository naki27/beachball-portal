# 0010 生年月日の入力部品（和暦）の細部

## 背景

A-16 で生年月日の入力部品（`src/components/ui/birth-date-field.tsx`）と、その純粋な処理（`src/lib/wareki.ts`）を作った。設計書 §4.3「生年月日の入力」は元号のボタン・「元年」は 1・「（1965年）・61歳」の表示・元号の範囲外のエラー・15 歳未満か 80 歳以上の確認・確認ページの「1965年（昭和40年）5月3日」を決めているが、次は決めていない。

1. 年齢の計算をどこに置くか（`src/lib/age.ts` は B-02 で作る予定だった）
2. 西暦で入れるときの年の範囲と、打っている途中の扱い
3. 西暦で入れたときの「（1965年）・61歳」の表示
4. 部品が親に何を知らせるか

## 決定

1. **`src/lib/age.ts` の `ageAt(birth, on)` をこのタスクで作る**。B-02 に書かれた規則（誕生日の当日に増える・2 月 29 日生まれは平年の 3 月 1 日に増える）とテストをそのまま入れた。B-02 では `deadline.ts` だけを作ればよい
2. 西暦は **1900 年から今日の年まで**。**4 けたになるまでは誤りを出さない**（打っている途中）。和暦は、年の上限（昭和 64・平成 31・令和は今日の年）を超えた時点で年の欄に誤りを出す。元号の始まり・終わりの日（昭和64年1月8日など）の誤りと今日より後の日付は、日の欄に出す
3. 西暦で入れたときは、そばに**和暦を添える**「（昭和40年）・61歳」。和暦で入れたときは設計書のとおり「（1965年）・61歳」
4. 部品は `{ date: "YYYY-MM-DD" | null, ready: boolean }` を知らせる。`ready` は、正しい日付があり、年齢の確認が要らないか「はい、合っています」を押したときだけ true。日付を変えると確認はやり直し
5. 年・月・日の欄は `autocomplete="off"`（代表者がほかの人の生年月日を入れる画面なので、自分の誕生日の自動入力を出さない。和暦の年の欄に西暦が入るのも防ぐ）

## 理由

- 1: 年齢の計算を 1 か所に保つ決まり（CLAUDE.md）があり、ほかの場所に仮の実装を書けない。B-02 の規則が決まっているので先に作っても食い違わない
- 2: 1900 年より前の生まれの選手はいない。途中で誤りを出すと、「19」と打っただけで赤くなり落ち着かない
- 3: 西暦をもう一度出しても打ち間違いの確かめにならない。和暦を添えると、元号で覚えている人が確かめられる
- 4: 「次へ進めない」を守るのは使う画面の側なので、判断に要る値だけを渡す

## 却下した代替案

- OS の日付ピッカー: 設計書が使わないと決めている（今日から遡るスクロールが長い）
- 年齢の確認を送信時にまとめて出す: §4.3 は入力のそばで確かめる形
