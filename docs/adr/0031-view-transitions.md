# 0031 ページの入れ替えに View Transitions を使う（本文だけのクロスフェード）

## 背景

設計書 §4.5 は「View Transitions API は対応ブラウザでだけ使う（未対応でも操作には影響しない）」とだけ書いていて、
**どこに使うか**は決めていなかった。U-05 で表の動きは行き渡ったが、**ページからページへ移った瞬間**だけは何の合図もなく、
内容が入れ替わったのか、押し間違えたのかが分かりにくかった。

§4.5 原則 1 は「飾りのための動きは入れない。楽しさは動きではなく、色・影・余白・カードの浮き・マウスを乗せたときの反応で出す」。
ページの入れ替えは**飾りではなく「変わった」を伝える合図**なので、ここには入れてよいと判断した。

## 決定

**`ViewTransition`（React）を、区画の layout で本文（`{children}`）だけに掛ける。**

- 置き場所: `src/app/(site)/layout.tsx` と `src/app/[slug]/layout.tsx` の 2 か所だけ。
  `<ViewTransition default="none" update="bb-page">` で、**中身が入れ替わったときだけ**動かす
- ヘッダ・電波の帯・フッタは外側にあるので動かない（利用者の目印が動かない）
- 動きは 200 ms のクロスフェード（`--motion-base`）。古い面が消え、新しい面が 6px 下からすっと入る。
  §4.5 原則 3「150〜300 ms」に収める
- **管理の案内（`AdminNav`）の「今いるところ」の緑の印だけ**は、`<ViewTransition name="admin-nav-current">` で
  前の項目から今の項目へ移る。印は 1 つだけなので名前がぶつからない
- 「視差効果を減らす」が ON のときは `::view-transition-*` の長さを 0 にする（内容は同じ・原則 5）
- 動いている間もページを押せるように `::view-transition { pointer-events: none }` を入れる

Next 16 の App Router では設定は要らない（React の canary が同梱されている。`node_modules/next/dist/docs/01-app/02-guides/view-transitions.md`）。
対応していないブラウザ（古い WebKit など）では**何も起きず、これまでどおり瞬時に入れ替わる**。アニメーション用のライブラリは入れていない（§4.5「実装」）。

## 理由

- 方向のあるスライド（左へ／右へ）は使わない。**どちらが「進む」かは画面によって違い**、迷いを生む。
  また §4.5 は「視差効果を減らす」で位置の動きを消すことを求めていて、スライドは影響が大きい
- ページごと（`page.tsx`）に `enter`/`exit` を書く方法もあるが、60 以上のページに同じ囲みを足すことになり、
  足し忘れた画面だけ動かない、という崩れ方をする。layout に 1 か所だけ置く方が、**全部の画面で同じ動き**になる

## 影響

- Server Action や `useTransition` で本文が描き直されたときも同じクロスフェードが起きる。
  「保存しました」などのメッセージが出るときに面が一度なじむので、これは望ましい動き
- 骨組み（`[slug]/admin/loading.tsx`・ADR 0029）から中身に変わるときもクロスフェードになる
- **E2E でスクリーンショットを撮るときは、入れ替えが終わるまで待つ**（`tests/e2e/screens.spec.ts` の `settled()`）。
  待たないと、半透明の途中の状態が写る

## 代わりに考えたこと

- **何もしない**: U-05 までの状態。入れ替わったことが分からない
- **ページの中身に `bb-rise-in` を掛ける**: 入れ替えのたびに全部が下から動くので、原則 3 の「短く控えめに」から外れる。
  また古い画面が消える所は表現できない
